# Verification evidence

All datasets are synthetic. No OU research data or production traffic is used. Measured runs, configured limits, and browser behavior are separate.

## Automated contracts

`TransferIntegrationTest.java` uses actual PostgreSQL 16.16. It covers manifest idempotency/conflict, boundaries/validation, capacity, authentication, locked downloads, corrupt and dishonest-length chunks, concurrent duplicates, conflicting content, out-of-order assembly, full-file hashing, stored corruption, cleanup, cancellation races, expiry, queued-work recovery, bounded storage retries, worker exclusion, backpressure, and actual HTTP downloads.

`ProcessRestartIT.java` runs a separate packaged application JVM. Each adapter test:

1. Generates an actual source and its SHA-256.
2. Starts with `-Xmx96m`, accepts two 8 MiB chunks, and forcibly kills the process.
3. Restarts on the same database/storage and verifies preserved receipts.
4. Flips a byte while supplying the original chunk hash; checks HTTP 422 and unchanged progress.
5. Uploads only missing parts and commits `VERIFYING`.
6. Kills the app again, restarts, and waits for `COMPLETED`.
7. Independently hashes the full streamed download.

Local tests use **128 MiB**, larger than the **96 MiB heap limit**. S3 tests use **24 MiB against Moto 5.2.5**, with real AWS SDK HTTP calls and multipart-copy assembly. The emulator is not AWS, a conformance suite, or a production benchmark.

The browser-domain tests compare incremental SHA-256 to `node:crypto` on empty, padding/block boundaries, random binary and multi-chunk input; they check source identity, resumed fixture generation, accepted progress, HTML escaping, and digest lifecycle.

## Raw records

Each process run saves `target/evidence/restart-local.json` and `restart-s3.json`. Checked-in [reference records](evidence) preserve timestamps, sizes, configured heap, sampled `/proc` high-water RSS, original/download digests, restart count, accepted/resumed part counts, elapsed orchestration time, and emulator scope. Elapsed time includes app startups; it is not isolated throughput.

RSS includes native memory, thread stacks, direct buffers, metaspace, and heap. It can exceed source size. The demonstrated claim is that a 128 MiB file completes under a 96 MiB **heap** limit, not a 96 MiB total-memory cap. Measurements vary by environment.

Runtime: Java 21, Spring Boot 3.5.16, PostgreSQL 16.16/Zonky, AWS SDK 2.59.5. With `S3_ENDPOINT` both process tests execute; without it the S3 test is explicitly skipped. The latest successful Actions run identifies the verified source commit. An earlier failing development run is not counted as a pass.

## Container and browser checks

The separate Actions container job builds the Dockerfile, starts non-root app plus PostgreSQL, uploads part of a 24 MiB file, sends SIGKILL to the app container, restarts with retained volumes, resumes missing parts, and verifies a streamed download. This checks packaging independently of Spring's test context.

The public sandbox uses actual generated bytes and IndexedDB transactions. Manual checks cover partial progress after reload, resume, corruption/retry, chunk inspection, filtering, receipts, verified download, and responsive layout. This verifies the JavaScript sandbox, not the backend. `scripts/package_demo.py` copies shared visual source; CI detects an outdated copy.

## Limits

- 32 GiB/20-session admission defaults are configuration, not tested production scale.
- Controlled race tests are not exhaustive concurrency proofs.
- Process death is not power loss, database failure, disk loss, or disaster recovery.
- Emulator success does not verify AWS IAM, regions, quotas, billing, or performance.
- Hash equality establishes declared byte equality, not meaning, safety, or provenance.
- Browser storage can be cleared/evicted; backend recovery requires its database and original storage.

## Reproduce

```bash
./mvnw -B verify
node --test scripts/browser-domain.test.mjs
```

For both adapters, start Moto and export `S3_ENDPOINT` as in the README. Actions performs this setup and uploads raw reports/evidence. Review digests and implementation alongside pass counts.
