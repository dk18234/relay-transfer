Corrupted chunk

Flip one byte while keeping the original digest. The chunk must be rejected, with no increase in accepted progress.

Expected: reject the chunk, then retry the original bytes.

Transfer all 24 chunks, independently hash the assembled bytes, then download the verified dataset and its receipt.

UNDER THE HOOD

Bytes are temporary.
Receipts are durable.

A transfer is a persistent manifest, a collection of immutable chunks, and a separately verified final object.

01 · Declare the original

The client streams through the source file to compute SHA-256, then creates an idempotent manifest with its exact byte length. The server fixes the chunk layout.

POST /api/transfers

02 · Accept verified chunks

At most four server upload slots stream into temporary disk files using a 64 KiB buffer. A checksum must pass before a storage key and receipt commit. A conflicting retry cannot replace an accepted part.

PUT /api/transfers/{id}/parts/{n}

03 · Survive the interruption

PostgreSQL stores accepted part numbers. The client re-hashes the selected source, fetches the manifest, and schedules only missing parts. Server restart does not reset progress.

GET /api/transfers/{id}

04 · Verify before publishing

A durable worker re-reads ordered parts, assembles the object, and independently re-reads the result. Only a matching complete SHA-256 unlocks download. S3 ETags are treated as receipts, not file hashes.

POST /api/transfers/{id}/complete

Deliberate engineering choices

One service, two storage adapters. The local adapter writes immutable chunk files and atomically renames a finished object. The S3 adapter stores immutable chunk objects and assembles them with multipart copy.

Clear ownership. Parent-row read locks admit different chunk uploads concurrently. Finalization and cancellation require a parent-row write lock. A finalizer holds its PostgreSQL transaction while working; process death releases that lock and leaves verification queued. This trades long database transactions for a small, explicit ownership model.

Measured scope. Local storage requires the persistent data volume and its database. The public sandbox uses IndexedDB, 1 MiB chunks, and a 64 MiB file limit. The Java backend defaults to 8 MiB chunks and a 32 GiB admission limit; admission is not a claim that a 32 GiB benchmark was run.
